# スコアリングロジック仕様

## 目的

カクヨム・なろうのランキングに掲載される小説の第1話を分析し、「AIポン出しテンプレート」の疑惑度をスコアとして算出する。

**これは「AI検出ツール」ではない。** LLM
を利用して執筆すること自体は問題としない。推敲・校正の痕跡がなく、LLM
出力をそのまま掲載しているもの（ポン出し）を検出対象とする。人間が書いた作品は、文章の巧拙にかかわらず弾かない。

**評価対象は文体の均質さ（明らかなテンプレート構文）に限る。**
題材・展開のテンプレ度（追放ざまぁ系など）や、読者個人の趣向は評価対象外とする。前者は文体が巧みであれば高スコアで通過してよく、後者は機械的に検証できない領域である。あくまで「明らかなポン出しテンプレート構文」を弾くガードレールと位置づける。

## 中心コンセプト: 均質さの検出 + 知覚的多様性

AI
ポン出し作品の構造的指紋は「均質さ」である。文の長さ、段落の構造、描写の解像度、会話の語尾パターンが、作品全体にわたって不自然に均一になる。人間が書く文章には必ずムラがある
— 気合いが入る場面と流す場面、得意な描写と苦手な描写。このムラの欠如を数値化する。

ただし統計的な多様性（SDやTTR）だけでは不十分な場合がある。AI生成テキストは数値上のバラつきを確保しつつ、読むと平坦・単調なテキストを生成できる。「統計的多様性」と「知覚的多様性」のズレを補完するために、感情表現の質（tell
vs
show）、文体の小説らしさ（論理接続詞の過多）、展開の構造的多様性（段落機能の遷移パターン）を追加指標として測定する。

## スコア

- 範囲: 0〜100（高いほど品質が高い = ポン出し疑惑が低い）
- デフォルト閾値: 40（これ以下をフィルタリング候補とする）
- 閾値はユーザーが popup UI から調整可能

## 判定理由の表示

スコアだけでなく、各指標がなぜ引っかかったかの理由を構造化データで返す。UI
側でユーザーに提示し、ブロックするかどうかの判断材料とする。

例: 「一文一段落比率が 85% と高い」「文長の標準偏差が 3.2 と極端に低い」

## レイヤー構成

### domain/analyzer — テキスト分析

ブラウザ API
に依存しない純粋関数群。入力としてテキスト（と必要に応じて形態素解析結果）を受け取り、生の統計値を返す。

### domain/scoring — スコア算出

analyzer
の出力を受け取り、正規化・重み付け・総合スコア算出を行う。正規化パラメータと重みの管理もこの層の責務。

### domain/tokenizer — 形態素解析ラッパー

lindera-wasm の初期化・キャッシュ管理。analyzer が必要とする形態素解析結果を提供する。

## スコア算出

```
base_score = (
  w1  * M1_normalized  +  // 一文一段落比率（反転）
  w2  * M2_normalized  +  // 文長SD
  w3  * M3_normalized  +  // 区切り頻度（反転）
  w4  * M4_normalized  +  // 会話語尾多様性
  w5  * M5_normalized  +  // TTR
  w6  * M6_normalized  +  // 描写密度の分散
  w7  * M7_normalized  +  // 段落長SD
  w8  * M8_normalized  +  // 体言止め分布
  w9  * M9_normalized  +  // 感情直接表現率（反転）
  w10 * M10_normalized +  // 論理接続詞密度（反転）
  w11 * M11_normalized +  // 段落遷移エントロピー
  w12 * M12_normalized +  // 文長バースティネス
  w13 * M13_normalized    // 地の文の平均字/行 (lineMetadata 派生)
) * 100 / Σw              // weight 合計で rescale して 100 満点に正規化

score = base_score × penalty_multiplier
```

候補 D (rev 20260812190006) で M13 (narrativeCharPerLine) を追加し weight 合計が 1.15 に
なった。既存 weight の按分はしない (按分は既存指標の「1 単位の意味」を変える) 方針のため、
合計を増やして Σweight で割る rescale を採る (Flesch 等の古典的可読性指標と同じ流儀)。 rescale
係数は定数ではなく Σweight から導出する (将来の weight 追加でも不変量が式のまま保たれる)。

M13 は RawMetrics ではなく lineMetadata から `narrative.charCount / narrative.lineCount` で 派生する
(`MetricConfig.deriveRawValue`)。lineMetadata が無い旧呼び出し・地の文 0 行では rawValue 0 = 寄与 0
として扱う。

### ペナルティ乗算方式

加算方式だけでは「1つの致命的な欠点が10個のまあまあな点に埋もれる」問題がある。ペナルティ乗算方式は、特定の指標の組み合わせが致命的閾値を下回った場合にスコア全体に乗算ペナルティを適用する。

ルールは 3 系統ある。いずれか一方だけを使う。

- **conditions ベース**: 既存の複合条件式。1 つ以上の `conditions`（AND 結合）と `penaltyMultiplier`
  を持ち、全条件が同時に満たされた場合のみ発動する。判定は RawMetrics の正規化値のみで行う
- **evaluate ベース**: RawMetrics に加えて lineMetadata の派生値（短行率など）を条件に
  取れる経路。`evaluate(rawMetrics, lineMetadata?) => boolean` 関数を持ち、`true` を返した場合に
  `penaltyMultiplier` を適用する。lineMetadata が undefined の場合、
  および測定不能条件（`narrative.lineCount === 0` など）では `evaluate` が `false` を
  返して非発火扱いにする（適用外を明示する）
- **grader ベース** (候補 D で導入): on/off ではなく連続値の multiplier を返す経路。
  `graderMultiplier(rawMetrics, lineMetadata?) => number` を持ち、1.0 = 非発火、1.0 未満で
  その値がそのまま min-mult 合成に参加する。閾値の僅超過と極端値を同じ強さで殴らない
  ための系統。測定不能条件では 1.0 を返す

複数のルールが発動した場合、発火した multiplier のうち **最小値 1 個だけ** を `base_score` に 掛ける
(min-mult 合成)。旧仕様は乗算合成 (`Π multiplier`) だったが、n=25 実測で二重発火時の
乗算合成が良側境界作品を過剰減点する事例が観測された (例: base 56.7 の良作品が
`一文一段落過多 (×0.75)` + `短行14 過多 (×0.80)` の乗算 0.60 で 34 まで潰され threshold=40
を割った)。 min-mult 合成に切り替えて、発火した個々の rule は `penalties`
配列に記録し続けたまま、実効 multiplier
だけ最小値に切り替えている。単発発火時は乗算/最小どちらも同値で、駄側の判別 (n=25 で 10/10 drop)
は温存される。

`exemptWhenZero: true` の条件は、生の値が 0（計測不能）の場合にルール全体を免除する （conditions
ベース側の仕組み）。

`calculateScore` のシグネチャは `calculateScore(rawMetrics, lineMetadata?)`。 lineMetadata
を省略した旧呼び出しは、evaluate ベースのルールが全て非発火となるため
本節導入前と等価な挙動になる（backward compatible）。

| ルール                   | 条件                                                                                         | 乗算係数                        | 根拠                                                                                                                                                                                                                                                                                                                                            |
| ------------------------ | -------------------------------------------------------------------------------------------- | ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文長の緩急・ばらつき不足 | M12 < 0.5 AND M2 < 0.45（M12免除あり）                                                       | ×0.55                           | 緩急がない AND 文長も均一 = AI的。緩急がないだけなら文体の個性の可能性がある                                                                                                                                                                                                                                                                    |
| 一文一段落の過多         | M1 < 0.30 AND M2 < 0.60                                                                      | ×0.85                           | 一文一段落比率が70%超でも文長SDが豊かなら紋切りではない（人気長編に多い）。文長SDも小さい（単調）ときに限り発動。 較正 n=24 で 0.65→0.75 に緩和後、候補 D (rev 20260812190006) で良側 (sspr>0.3 & SD<15 帯の良作) への発火が残っていたため 0.85 にさらに緩和。代償の駄側透過は holdout 検証込みで受容 (experiments/20260812-holdout/results.md) |
| 地の文短行14 の過多      | `ratio = narrative.short14 / narrative.lineCount > 0.30`（lineMetadata 参照、grader ベース） | `max(0.55, 1 − (ratio − 0.30))` | 候補 D で on/off (×0.80 一律) から grade 化。31% と 79% を同じ強さで殴る段差が良側境界作品の巻き込み主因だったため、比率に比例する連続 multiplier に置き換えた。50% で旧 on/off 相当の ×0.80、floor 0.55 で下げ止まる。lineMetadata undefined、または `narrative.lineCount === 0` は測定不能で非発火 (1.0)                                      |

### 表示較正カーブ（集約段の 13 本目の normalize）

`base_score × penalty_multiplier` で得た値を、最終的にバッジへ表示する スコアに変換する単調関数 f
を通す。これは表示ハックではない — M1〜M12 の 12 本の指標 normalize と同格の、集約段に置かれた 13
本目の normalize であり、domain/scoring 層に閉じた決定的関数である。

**何を解くか**

現行式は較正 n=24 で駄検出 0/10（完璧）を達成しているが、良ラベルの スコア分布が min=30, median=60,
max=81 と広く、49-58 帯の良作 （崩界のオブリテレーター 49、忘れられ令嬢 49 等）が「49」のバッジで
読み飛ばされる。判別情報は評価関数内に既に存在しており、問題は
表示尺度の較正であって情報量ではない。

**契約**

f は次の 4 条件を満たす:

1. **単調性**: 任意の x1 < x2 に対し f(x1) ≤ f(x2)
2. **固定点**: f(40) = 40（DEFAULT_THRESHOLD との整合）
3. **C1 連続**: 制御点で導関数が連続
4. **判定集合の不変性**: 任意の作品スコア s について「s > 40」と 「f(s) > 40」が同値。これは 1 と 2
   の系だが、テストで独立に固定する

条件 1・2 の系として、ゲート通過集合は較正の前後で**構成的に**（数学的に、
実データに依存せず）一致する。パーセンタイル表示のような母集団依存の 変換とは数学的身分が異なる —
較正カーブは作品自身のスコアだけから
決まる決定的関数であり、他作品との相対順位や母集団分布に依存しない。

**実装形式**

単調保持 3 次エルミート補間（PCHIP, Piecewise Cubic Hermite Interpolating Polynomial,
Fritsch-Carlson 1980）を採用する。制御点間の傾きを局所的に
決めることでオーバーシュートせず、単調性と C1 連続性を同時に保証する。

初期制御点（後続の較正データで再フィット可能）:

| x   | f(x) |
| --- | ---- |
| 0   | 0    |
| 40  | 40   |
| 50  | 52   |
| 60  | 65   |
| 75  | 80   |
| 100 | 100  |

想定効果（n=24 ラベル済み）:

- 良 second-min: 49 → 51（崩界の表示改善）
- 良 median: 60 → 65
- 駄 max: 39 → 39（除外維持）
- 中間帯 40-69 の作品数: 76 → 55 件で保持（急減しない）
- 通過/除外集合: 全 129 件で変換前後ビット一致（契約 4）

**制御点の性質と決定手続き**

制御点は較正データセットに対する目視確認で決める（cal_viewer で正本
スコアと較正後スコアを並列表示、良ラベル分布・中間帯保持度・境界
マージンを確認）。より攻めた制御点（例: (50,63)(65,78)）は良 second-min を 61
まで持ち上げる代わりに、中間帯 40-69 が 76→19 件に激減し 分布が 2
極化する。表示改善と分布連続性のトレードオフとして、 moderate 側から出発する。

**再較正の条件**

- ラベル済みサンプルが n≈90 に達し、指標側の再アンカー（第二層作業）が
  完了した時点で、制御点を再フィットする
- Cohen's d の絶対値が |d|≳1 で信用できる符号が確定した後は、指標 weight・normalize アンカー・invert
  設定の一括再設計と併せて再較正

**判別 4 指標への再配分の設計選択**:

削減 weight 0.26 の再配分は 2 パターンを比較した:

- パターン B (判別 5 指標に均等按分、M1 一文一段落 0.30 → 0.43): 良側の一文一段落が高い
  作品を過剰減点、良 gate 12/15 で FAIL
- パターン C (M1 据え置き、他 4 指標に按分、採用): 良で高い判別 4 指標に集中させ、良側
  寄与を保つ設計。良 13/15 + 駄 0/10 gate 通過

**受け入れゲート** (Fable 裁定 E4):

weights_experiment 段階の候補を canonical へ反映する前に以下を満たす:

1. 良 pass >= 13/15 (ラベル済み)
2. 駄 pass == 0/10 (ラベル済み)
3. 契約 4: ラベル済み集合の pass-fail 保存 (n=25 で不変)

未ラベル境界作品の flip は許容 (gate 判断は含まない)。

**留意事項** (Fable 裁定 D3):

- **d の順位で weight 微調整するのは禁止**: n=25 で SE≈0.4、d は序数的 (採用/廃止/保留の 3 値判断)
  にのみ使い、weight の小数第 2 位を d で正当化しない
- narrativeShort14Ratio の weight 化は家族 0 の実測で「駄側の境界作品を良側寄与で押し
  上げる」問題により見送り。narrative シグナルは短行14 penalty の multiplier 微強化 (0.85 → 0.80)
  で活用

## 判定理由の構造

```typescript
interface ScoreResult {
  score: number; // 0-100（表示較正カーブ f を通し round した最終値）
  metrics: MetricResult[]; // 12 指標それぞれの詳細
  penalties: PenaltyResult[]; // 発火した複合ペナルティのラベルと乗算係数
  openingType?: OpeningFormat; // 第1話の形式判定結果（キャラ紹介 / 掲示板 / 短文 / 通常）
  sampledCount?: number; // 再評価で取得・調査した話数（1 = 第1話のみ）
  targetEpisodeIndex?: number; // 採点対象の話番号（0 = 第1話。1 以上で「N話で再評価」表記）
  lineMetadata?: LineMetadata; // 行ベース診断メタデータ（line-metadata.md 参照）
}

interface MetricResult {
  key: string; // "sentenceLengthSD" 等
  label: string; // "文長の標準偏差"
  rawValue: number; // 生の統計値
  normalizedValue: number; // 0-1 正規化後
  weight: number; // 重み
  contribution: number; // スコアへの寄与（normalized * weight * 100）
  flagged: boolean; // 閾値を下回ったか
  reason: string; // "文長の標準偏差が 3.2 と極端に低い"
}

interface PenaltyResult {
```

## サンプリング戦略: 開幕話の形式判定と再採点

基本は第1話を分析対象とする。ただし第1話の内容によっては作品全体の文体を代表せず、偽陽性（良い作品を低スコアにする）を生む。これを避けるため、第1話の「形式」を判定し、判定結果に応じて追加の話を読み込んで再採点する。

### 形式判定

第1話を以下の4形式に分類する。

| 形式       | 判定方法                                                                                                                                                                                                    |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 通常       | 以下に該当しない                                                                                                                                                                                            |
| 短文       | 文数が30未満（文長バースティネスが計測不能なライン。30文未満ではバースティネスが0を返すため）                                                                                                               |
| キャラ紹介 | エピソードタイトルに「キャラ」「登場人物」「人物紹介」「プロフィール」「設定」等を含む、または本文が「名前（ふりがな）／年齢／身長／特徴」のプロフィール列挙や「追記:」「Q:」「A:」等の定型構造で構成される |
| 掲示板     | エピソードタイトルに「掲示板」「スレ」「Part」等を含む、または本文が「レス番号: 名無し」形式の行・「>>番号」アンカーで構成される                                                                            |

タイトルのキーワードは補助、本文の構造シグナルを一次判定とする。検出は「誤報しても害がない」方針。通常の物語話を誤って非ナラティブと判定しても、次話で再採点するだけだから実害がない。逆に非ナラティブを見逃すと偽陽性が残るため、漏れを減らすことを優先する。

### 追加取得と再採点

- 形式がキャラ紹介・掲示板・短文の場合、次の話を追加取得して再採点する
- 追加取得は最大3話まで。通常形式の話が見つかればそこで停止する
- 追加取得中に取得に失敗した場合（話の削除・非公開・アクセス制限）も終端とする
- 全話が非ナラティブ形式の場合（例:
  作品全体が掲示板形式）や、追加話が存在しない一話完結の短編でも、スコアは必ず出力する。その場合は第1話の内容で採点する

### 統合方式

- 複数話を取得した場合、原則として1話のみを採点対象にする（連結しない）。複数話を1本のテキストに連結すると、話をまたぐ統計的な分布が混ざり、文長SDやバースティネスの値が歪むため
- 例外は「通常形式だが短文」の場合のみ。このときは文数が30文に達するまで次の話を累積連結し、その結果を採点する

### 表示

スコアには判定の文脈を添える。

- 開幕形式のラベルは常に表示する（例:
  「キャラ紹介開幕」「掲示板開幕」）。ランキングカードはバッジのツールチップ内に、作品ページは詳細パネル内に表示し、ブラウザのネイティブ
  title は使わない（自前ツールチップと二重に出るため）
- 採点対象が第1話以外の話になった作品（再採点）は、開幕形式ラベルに加えて「N話で再評価」を表示する
- 第1話のまま採点した作品（通常開幕や、全話が非ナラティブでフォールバックした場合）は形式ラベルのみを表示し、再評価表記は付けない

## 将来の拡張候補（現時点では未実装）
