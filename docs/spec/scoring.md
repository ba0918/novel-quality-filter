# スコアリングロジック仕様

## 目的

カクヨム・なろうのランキングに掲載される小説の第1話を分析し、「AIポン出しテンプレート」の疑惑度をスコアとして算出する。

**これは「AI検出ツール」ではない。** LLM
を利用して執筆すること自体は問題としない。推敲・校正の痕跡がなく、LLM
出力をそのまま掲載しているもの（ポン出し）を検出対象とする。人間が書いた作品は、文章の巧拙にかかわらず弾かない。

## 中心コンセプト: 均質さの検出 + 知覚的多様性

AI
ポン出し作品の構造的指紋は「均質さ」である。文の長さ、段落の構造、描写の解像度、会話の語尾パターンが、作品全体にわたって不自然に均一になる。人間が書く文章には必ずムラがある
— 気合いが入る場面と流す場面、得意な描写と苦手な描写。このムラの欠如を数値化する。

ただし統計的な多様性（SDやTTR）だけでは不十分な場合がある。AI生成テキストは数値上のバラつきを確保しつつ、読むと平坦・単調なテキストを生成できる。「統計的多様性」と「知覚的多様性」のズレを補完するために、感情表現の質（tell
vs
show）、文体の小説らしさ（論理接続詞の過多）、展開の構造的多様性（段落機能の遷移パターン）を追加指標として測定する。

## スコア

- 範囲: 0〜100（高いほど品質が高い = ポン出し疑惑が低い）
- デフォルト閾値: 40（これ以下をフィルタリング候補とする）
- 閾値はユーザーが popup UI から調整可能

## 判定理由の表示

スコアだけでなく、各指標がなぜ引っかかったかの理由を構造化データで返す。UI
側でユーザーに提示し、ブロックするかどうかの判断材料とする。

例: 「一文一段落比率が 85% と高い」「文長の標準偏差が 3.2 と極端に低い」

## レイヤー構成

### domain/analyzer — テキスト分析

ブラウザ API
に依存しない純粋関数群。入力としてテキスト（と必要に応じて形態素解析結果）を受け取り、生の統計値を返す。

### domain/scoring — スコア算出

analyzer
の出力を受け取り、正規化・重み付け・総合スコア算出を行う。正規化パラメータと重みの管理もこの層の責務。

### domain/tokenizer — 形態素解析ラッパー

lindera-wasm の初期化・キャッシュ管理。analyzer が必要とする形態素解析結果を提供する。

## 指標一覧

### コア指標（判別力が高い）

| #  | 指標                       | 計測方法                                                                                | AIポン出しのサイン                               | 正規化                             |
| -- | -------------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------ | ---------------------------------- |
| M1 | 一文一段落比率             | 段落を改行で分割、会話文を除外し、句点が1つ以下の段落の比率を算出                       | 80% 以上（全編一文一段落の羅列）                 | `1 - ratio`（低いほど良い → 反転） |
| M2 | 文長の標準偏差             | 文を句点で分割、各文の文字数の標準偏差                                                  | SD < 5（文の長さがほぼ均一）                     | `min(SD / 30, 1)`                  |
| M3 | 水平線/区切りの頻度        | `---`, `＊＊＊`, `***`, `───` 等を正規表現で検出、文数に対する比率                      | 10回以上/話                                      | `1 - min(frequency * 10, 1)`       |
| M4 | 会話文の語尾パターン多様性 | 会話文（「」内）を抽出 → 形態素解析で末尾トークンの品詞パターンを分類 → ユニーク数/総数 | パターンが少ない（キャラの口調が分化していない） | `min(variety, 1)`                  |

### 補助指標（コア指標との組み合わせで効果を発揮）

| #  | 指標                 | 計測方法                                                        | AIポン出しのサイン                                    | 正規化                              |
| -- | -------------------- | --------------------------------------------------------------- | ----------------------------------------------------- | ----------------------------------- |
| M5 | 語彙多様性（TTR）    | 形態素解析で内容語を抽出 → ユニーク表層形数 / 総表層形数        | 低い                                                  | `min(TTR / 0.8, 1)`                 |
| M6 | 描写密度の分散       | 段落ごとの修飾語（形容詞+副詞）密度を算出 → その標準偏差        | SD が低い（全体が同じ解像度）                         | `min(SD / 0.05, 1)`                 |
| M7 | 段落長の標準偏差     | 段落ごとの文字数の標準偏差                                      | SD が低い（段落構造が平板）                           | `min(SD / 50, 1)`                   |
| M8 | 体言止め分布の均一性 | 文末が名詞で終わる文の分布を区間ごとに集計 → 分布のエントロピー | エントロピーが高い（均等にばらまかれている = 人為的） | `1 - min(entropy / max_entropy, 1)` |

### 知覚的多様性指標（統計的多様性を補完）

| #   | 指標                 | 計測方法                                                                                                           | AIポン出しのサイン                                          | 正規化                      |
| --- | -------------------- | ------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------- | --------------------------- |
| M9  | 感情直接表現率       | 地の文（「」外）を形態素解析、感情語辞書（感情形容詞・感情名詞・心理動詞）にマッチするトークンの内容語に対する比率 | 高い（感情を直接名指しする tell 偏重 = 描写の解像度が低い） | `1 - min(ratio / 0.08, 1)`  |
| M10 | 論理接続詞密度       | 地の文中の論理接続表現（しかし・そのため・つまり等）の出現数 / 地の文の文数                                        | 高い（評論文的な文体 = 小説として不自然）                   | `1 - min(density / 0.3, 1)` |
| M11 | 段落遷移エントロピー | 段落を機能分類（会話D/内面I/描写N/行動A）→ 2-gram遷移の条件付きエントロピー                                        | 低い（同じサイクルの繰り返し = 構造的に単調）               | `min(entropy / 1.5, 1)`     |
| M12 | 文長バースティネス   | 10文窓ごとの文長SDを計算 → そのSD（バラつきのバラつき）。30文未満はフォールバック値0                               | 低い（全区間で同じバラつき = 緩急がない = 平坦）            | `min(burstiness / 8, 1)`    |

## スコア算出

```
base_score = (
  w1  * M1_normalized  +  // 一文一段落比率（反転）
  w2  * M2_normalized  +  // 文長SD
  w3  * M3_normalized  +  // 区切り頻度（反転）
  w4  * M4_normalized  +  // 会話語尾多様性
  w5  * M5_normalized  +  // TTR
  w6  * M6_normalized  +  // 描写密度の分散
  w7  * M7_normalized  +  // 段落長SD
  w8  * M8_normalized  +  // 体言止め分布
  w9  * M9_normalized  +  // 感情直接表現率（反転）
  w10 * M10_normalized +  // 論理接続詞密度（反転）
  w11 * M11_normalized +  // 段落遷移エントロピー
  w12 * M12_normalized    // 文長バースティネス
) * 100

score = base_score × penalty_multiplier
```

### ペナルティ乗算方式

加算方式だけでは「1つの致命的な欠点が10個のまあまあな点に埋もれる」問題がある。ペナルティ乗算方式は、特定の指標の組み合わせが致命的閾値を下回った場合にスコア全体に乗算ペナルティを適用する。

- 各ペナルティルールは1つ以上の `conditions`（AND 結合）と `penaltyMultiplier` を持つ
- 全条件が同時に満たされた場合のみペナルティが発動する（複合条件）
- 複数のルールが発動した場合、乗算は累積する
- `exemptWhenZero: true` の条件は、生の値が0（計測不能）の場合にルール全体を免除する

| ルール                 | 条件                                   | 乗算係数 | 根拠                                                                         |
| ---------------------- | -------------------------------------- | -------- | ---------------------------------------------------------------------------- |
| 緩急+均質の複合        | M12 < 0.5 AND M2 < 0.45（M12免除あり） | ×0.55    | 緩急がない AND 文長も均一 = AI的。緩急がないだけなら文体の個性の可能性がある |
| 一文一段落の極端な多用 | M1 < 0.30                              | ×0.65    | 一文一段落比率が70%超はスカスカ文体。単独でも致命的                          |

### 初期重み

| 指標                     | 重み | 理由                                                                         |
| ------------------------ | ---- | ---------------------------------------------------------------------------- |
| M1 一文一段落比率        | 0.30 | 最強のシグナル。スカスカ文体の検出力が高く、人間/AI差が大きい                |
| M2 文長SD                | 0.12 | 均質さの直接指標                                                             |
| M3 区切り頻度            | 0.07 | AI特有だが出ない作品もある                                                   |
| M4 会話語尾多様性        | 0.08 | キャラ分化の欠如を検出                                                       |
| M5 TTR                   | 0.06 | 文章量による影響が大きい                                                     |
| M6 描写密度の分散        | 0.05 | 均質さの核心指標                                                             |
| M7 段落長SD              | 0.05 | 構造の平板さを検出。M1 と相関が高いため補助的に                              |
| M8 体言止め分布          | 0.02 | 補助的                                                                       |
| M9 感情直接表現率        | 0.07 | tell偏重の検出。統計的多様性が高くても知覚的に平坦なケースを補完             |
| M10 論理接続詞密度       | 0.06 | 評論文的文体の検出。モデル変化にロバスト                                     |
| M11 段落遷移エントロピー | 0.04 | 構造的単調さの検出。段落機能の反復パターンを捕捉                             |
| M12 文長バースティネス   | 0.08 | 緩急の検出。AI=2.77 vs 人間=6.98 で2.5倍差。M2（全体SD）の不均一性を補完する |

重みは fixture データでの検証結果に基づいて調整する。合計は 1.0。

## 判定理由の構造

```typescript
interface ScoreResult {
  score: number; // 0-100
  metrics: MetricResult[]; // 各指標の詳細
}

interface MetricResult {
  key: string; // "sentenceLengthSD" 等
  label: string; // "文長の標準偏差"
  rawValue: number; // 生の統計値
  normalizedValue: number; // 0-1 正規化後
  weight: number; // 重み
  contribution: number; // スコアへの寄与（normalized * weight * 100）
  flagged: boolean; // 閾値を下回ったか
  reason: string; // "文長の標準偏差が 3.2 と極端に低い"
}
```

## テスト検証基準

fixture はコード名で管理する（作品名・作者名は fixture ファイルに含めない）。

| fixture コード名  | 期待スコア  | 特徴                                             |
| ----------------- | ----------- | ------------------------------------------------ |
| high-quality-01   | 70 以上     | 人間執筆。自然な緩急、キャラ分化、描写の濃淡あり |
| high-quality-02   | 70 以上     | 人間執筆。独自の文体                             |
| low-quality-01    | 40 以下     | AIポン出し。一文一段落、均質な文長、語尾分化なし |
| false-positive-01 | 40 を超える | 人間の努力作を誤って弾かないことの検証           |

## サンプリング戦略: 開幕話の形式判定と再採点

基本は第1話を分析対象とする。ただし第1話の内容によっては作品全体の文体を代表せず、偽陽性（良い作品を低スコアにする）を生む。これを避けるため、第1話の「形式」を判定し、判定結果に応じて追加の話を読み込んで再採点する。

### 形式判定

第1話を以下の4形式に分類する。

| 形式       | 判定方法                                                                                                                                                                                                    |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 通常       | 以下に該当しない                                                                                                                                                                                            |
| 短文       | 文数が30未満（文長バースティネスが計測不能なライン。30文未満ではバースティネスが0を返すため）                                                                                                               |
| キャラ紹介 | エピソードタイトルに「キャラ」「登場人物」「人物紹介」「プロフィール」「設定」等を含む、または本文が「名前（ふりがな）／年齢／身長／特徴」のプロフィール列挙や「追記:」「Q:」「A:」等の定型構造で構成される |
| 掲示板     | エピソードタイトルに「掲示板」「スレ」「Part」等を含む、または本文が「レス番号: 名無し」形式の行・「>>番号」アンカーで構成される                                                                            |

タイトルのキーワードは補助、本文の構造シグナルを一次判定とする。検出は「誤報しても害がない」方針。通常の物語話を誤って非ナラティブと判定しても、次話で再採点するだけだから実害がない。逆に非ナラティブを見逃すと偽陽性が残るため、漏れを減らすことを優先する。

### 追加取得と再採点

- 形式がキャラ紹介・掲示板・短文の場合、次の話を追加取得して再採点する
- 追加取得は最大3話まで。通常形式の話が見つかればそこで停止する
- 追加取得中に取得に失敗した場合（話の削除・非公開・アクセス制限）も終端とする
- 全話が非ナラティブ形式の場合（例:
  作品全体が掲示板形式）や、追加話が存在しない一話完結の短編でも、スコアは必ず出力する。その場合は第1話の内容で採点する

### 統合方式

- 複数話を取得した場合、原則として1話のみを採点対象にする（連結しない）。複数話を1本のテキストに連結すると、話をまたぐ統計的な分布が混ざり、文長SDやバースティネスの値が歪むため
- 例外は「通常形式だが短文」の場合のみ。このときは文数が30文に達するまで次の話を累積連結し、その結果を採点する

### 表示

スコアには判定の文脈を添える。

- 再採点した作品は、ツールチップで「N話で再評価」と採点基準が変わったことを明示する
- 非ナラティブ形式で採点した作品は、ツールチップで形式を明示する（例:
  「キャラ紹介開幕」「掲示板開幕」）

## 将来の拡張候補（現時点では未実装）

- ナレーション的引きのパターン（「そして○○はまだ知らない」系）
- 誤字脱字の不自然な少なさ（計測が困難）
- プロット不要な細部の存在/欠如（統計的に測りにくい）
- 語用論的不自然さ（AI特有の言い回し検出 — モデル変化で陳腐化するため保留）
