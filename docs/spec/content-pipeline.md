# コンテンツパイプライン仕様

## 概要

ランキング等のページ上で作品カードを検出し、スコアリング → バッジ表示 → フィルタリングを
行うパイプラインの仕様。共通フローとサイト固有の実装に分離する。

## 共通フロー

```
1. ページロード / DOM 変更検出
2. 作品カードを走査
3. 各カードから workId, workUrl を抽出
4. 未処理のカードに対し background に SCORE_WORK メッセージ送信
5. 応答を受けてバッジ DOM 注入
6. 閾値以下のカードにフィルタリング表示を適用
```

## カクヨム固有仕様

### 対象ページ

| ページ種別 | URL パターン                        |
| ---------- | ----------------------------------- |
| ランキング | `https://kakuyomu.jp/rankings/*`    |
| 検索結果   | `https://kakuyomu.jp/search*`       |
| 新着       | `https://kakuyomu.jp/recent_works*` |

### カード検出

作品カードの DOM セレクタはカクヨムの実際の DOM 構造に合わせて決定する。 content script
のロード時に初回走査を行い、MutationObserver で動的追加にも対応する。

カードから抽出する情報:

- **workId**: 作品ページへのリンク href (`/works/{workId}`) から正規表現で抽出
- **workUrl**: 作品ページの完全 URL（`https://kakuyomu.jp/works/{workId}`）
- **カード要素**: バッジ注入先の参照

### 第1話テキスト取得（background 側で実行）

2段階 fetch:

```
1) GET /works/{workId}
   → 目次ページの HTML をパース
   → 第1話のエピソードリンクを取得

2) GET /works/{workId}/episodes/{episodeId}
   → エピソード本文のテキストを抽出
```

セレクタはカクヨムの実際の DOM 構造に基づいて実装時に確定する。

### rate limiting

- background の fetch キューで制御
- fetch 間隔: 1秒（1回の fetch 完了後、次の fetch まで 1 秒待機）
- 1 作品あたり最大 2 回の fetch（作品ページ + 第 1 話）
- ランキング 50 作品の場合、全件キャッシュ miss で最大約 100 秒

## SPA 対応

カクヨムはページ内遷移（pushState ベース）を行う場合がある。

- `MutationObserver` で `document.body`（またはコンテンツ領域）の `childList` 変更を監視
- 新しいカード要素が追加されたら、未処理のもののみスコアリングキューに追加
- 処理済みカードは `data-nqf-scored` 属性で識別（二重処理防止）

## バッジ表示

### スコアバッジ

- カードの右上（または適切な位置）に小さなバッジとして表示
- 表示内容: スコアの数値（整数）
- 背景色: スコアに応じたグラデーション
  - 0-35: 赤系（`hsl(0, 70%, 50%)`）
  - 36-65: 黄系（`hsl(40, 70%, 50%)`）
  - 66-100: 緑系（`hsl(120, 50%, 40%)`）
- 中間値は HSL の色相を線形補間

### ツールチップ

バッジにホバーすると、flagged な指標の理由を表示:

```
⚠ 一文一段落比率が 85% と高い
⚠ 文長の標準偏差が 3.2 と極端に低い
⚠ 描写密度の分散が低い
```

- `MetricResult.flagged === true` の指標のみ表示
- `MetricResult.reason` をそのまま使用

### 容疑者表示（閾値以下）

- カード全体に `opacity: 0.35` を適用
- CSS トランジション付き（急に薄くなると驚くため）

### 再スコア

- バッジクリックで `RESCORE_WORK` メッセージを送信
- クリック中はバッジを「...」に差し替え
- 結果が返ったらバッジを更新

## スタイル設計

- すべての CSS クラス / data 属性に `nqf-` プレフィックスを付与
- カクヨムの既存スタイルとの衝突を回避
- スタイルは JS から `<style>` 要素として注入（content script は CSS
  ファイルを直接読み込めないため）

## 閾値

- 現時点では `DEFAULT_THRESHOLD` (35) をハードコード
- popup UI での閾値変更は次回スコープ
