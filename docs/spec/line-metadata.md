# 行ベース文体メタデータ仕様

## 目的

既存のスコアリング（12指標 M1〜M12）は、文長や段落構造の均質さを測るが、
「会話・メタ表示・短い行の密度」＝1行あたりの情報量の少なさは測っていない。
その結果、セリフ主体でステータス窓や短い行を並べただけの、地の文がほとんど
ない作品が、閾値（40点）を超えてすり抜ける。地の文を抽出する処理が会話文
（「」）を除去するため、会話が大半の作品は分析対象の地の文が乏しくなり、
既存指標が乏しい材料の上で無警戒に高い値を出してしまうのが原因である。

本仕様は、本文を行（段落）単位で分類し、カテゴリごとの分量・短さを集計した
診断用メタデータを追加する。狙いは、この「1行の情報量が少ない」作品の可視化。

## 位置づけ：まず表示専用、のちに評価軸

- 当面は作品ページに表示する診断用データ。総合スコア（0〜100）には一切寄与しない。
- 実データでの較正で有望と確認できた指標だけを、後日スコアの評価軸へ昇格する
  二段構えとする（昇格は本仕様のスコープ外・将来の作業）。

## 対象範囲

- 集計対象は作品「全体」ではなく、既存のサンプリング戦略（開幕形式を判定して
  通常の物語話を選ぶ、scoring.md 参照）で選ばれた採点対象の本文（サンプル対象）。
- 本文の抽出と行分類はサイトごとに実装を分離する。まずカクヨムに対応し、なろうは
  後追い。理由は空行の目印がサイトで異なるため（下記）。行を数える集計処理は共通。

## 行の分類

カクヨムでは1回の改行が1つの段落（HTMLの `<p>` タグ）になる。この1行（＝1段落）を、
次の6カテゴリのいずれか1つへ排他的に分類する。優先順位は上から順に判定し、最初に
当てはまったカテゴリで確定する。

1. **空行** — 中身のない行。カクヨムでは空行に `blank` という目印（CSSクラス）が
   付くので、それを数える。
2. **区切り線** — ダッシュ等の記号だけが連続して1行を構成する行（`――――`・`---` 等）。
3. **メタ行（確定）** — 行の先頭が `【` `《` `◆` `■` 等の装飾記号、または `～…～` で
   全体が囲まれた行。`【ステータス】`・`《ＨＰ》`・`～入学初日～` のような非本文の 構造・見出し行。
4. **セリフ行** — 行の末尾が `」` または `』` で終わる行。`「痛いよ」` だけでなく、 話者名付きの
   `カイト 「痛いよ」`（脚本形式）も末尾が `」` なのでここに入る。
5. **地の文** — 句点（`。`）で終わる通常の行。
6. **非文末行** — 上のどれでもなく、句点でも閉じ括弧でも終わらない行。体言止め、
   演出的に途中で切った改行、内心 `（…）` の取りこぼしなどが混ざる生カウント。

### 判定の設計方針

- メタ行はセリフより先に判定する。`【レベル】…『９５』` のように末尾が `』` で終わる
  ステータス行を、セリフへ誤分類しないため。
- メタ行は「行の先頭が記号」で判定する。`彼は【勇者】と呼ばれた。` のように文の途中に `【】`
  がある地の文を、誤ってメタ扱いしないため。
- メタ行の記号セットは定数として切り出し、後から（較正で）追加できるようにする。
- 分類の誤りは許容する。雑な書き方でセリフや内心が地の文／非文末に化けても、短い行が
  増えてスコアが下がる方向に働き、目的（雑な文体を低評価）と一致するため。病的な入力に
  合わせた完璧な分類は目指さない。

## 短文と短チャンク

「短さ」を2つの単位・複数の閾値で数える。

- **行** — 1段落（`<p>`）そのもの。
- **句点チャンク** — 1行を句点（`。`）で区切った断片。句点がない行も1チャンクと数える （常に
  チャンク数 ≥ 行数）。行と句点チャンクのズレは「1行に何文を詰め込んでいるか
  ＝改行演出の強さ」を表す。
- **閾値** — 20字未満・30字未満 に加え、較正実験用に **14字未満** も集計する（2026-08-11 追加）。 14
  は「良作品は 15-16 字帯に密度ある完成短文を置く傾向」を守りつつ「駄作品のト書き・独白
  垂れ流し帯（12-14）を強く検出する」ための候補閾値。data (dataset.jsonl / cal.json) には 14/20/30
  すべて残すが、**表示に並べる閾値はサーフェスごとに差がある**（下記「表示」節）。
  スコア・ペナルティ・警告閾値には使わない。14 は 20/30 より狭い区間で警告閾値 （率 >
  0.5）に達しやすく、閾値の意味を歪めるため。閾値の判別力は後段の較正で比較する。
- 文字数は、空白と全角スペースを除いた文字数で数える。ルビ（漢字の読み）は含めない。

句点チャンクの分割は句点（`。`）のみで行い、`！`・`？`・セリフの `」` では分割しない。
短チャンクは地の文でのみ数える（セリフ・メタ・非文末は句点区切りが意味を持たないため、
行単位のみ）。

## データモデル

サンプル対象本文から集計し、スコアのキャッシュ（cache.md）に次のメタデータを付与する。

    metadata: {
      総行数, 総文字数,           // 総文字数は空白除去後
      空行数,                     // blank クラスの <p>
      区切り線数,                 // ダッシュ等の連続で行全体が構成される行

      地の文: { 行数, 文字数, チャンク数, 短行14, 短行20, 短行30, 短チャンク14, 短チャンク20, 短チャンク30 },
      セリフ: { 行数, 文字数, 短行14, 短行20, 短行30 },   // 末尾が 」or 』
      メタ:   { 行数, 文字数, 短行14, 短行20, 短行30 },   // 行頭が 【《◆■ 等 or ～囲み
      非文末行: { 行数, 文字数, 短行14, 短行20, 短行30 },
    }

- 率（短行率・セリフ率など）は保存しない。分子（短い行の数）と分母（行数・文字数）
  だけを持ち、表示時に必要な率を組み立てる。こうすると「セリフを除いた短行率」
  「メタを含めた率」など、後から自由に計算できる。
- 文字数はカテゴリごとに持つ。行数だけからは復元できないため。副産物として `文字数 ÷ 行数`
  で「1行あたり平均文字数（＝情報量の密度）」がカテゴリ別に得られる。

## 空行の正確なカウントと後方互換

`blank` クラスによる正確な空行判定には、本文抽出の段階でこの構造情報を保持する必要が
ある。現在の抽出処理は装飾情報を落とし連続改行も圧縮するため、これを改める。後方互換は
考慮しない。スキーマバージョンを上げた時点で既存キャッシュは全て破棄し、次回アクセス時に
再採点する（cache.md のスキーマ版管理に従う）。

## 表示

作品ページの詳細パネル（content-pipeline.md、スコア内訳を表示する展開領域）に、この
層別メタデータを、既存のメトリクス一覧とは別セクションとして表示する。総合スコアの数値や
ペナルティには影響しない。表示する率はすべて保存済みの分子（各カウント）と分母（総行数・
総文字数）から算出し、率自体は保存しない。

- **折りたたみ**: セクションは開閉式で、デフォルトは畳んだ状態。見出し右に、畳んだままでも
  読めるダイジェスト（平均文字数/行・空行率）を出す。
- **サマリ**: 総行数・総文字数（実数）と、空行・区切り線を「数（率）」で併記する。
- **見出しスカラー（薄さ）**: 「平均文字数/行 = 総文字数 ÷（総行数 − 空行数）」と「地の文の
  短行率（30字）」の2つをチップで強調する。全カテゴリを混ぜた総合短行率は出さない（セリフ・
  メタ・非文末は構造的に短く判別力を失うため）。平均文字数/行の分母が0のときは表示を退避する。
- **構成バー**: 行の内訳（6カテゴリの行割合＝空行・区切り線を含む）を積み上げバーと凡例で示す。
- **カテゴリ別**: 地の文・セリフ・メタ・非文末について、行数（行割合）・文字数（文字割合）・
  短行率と短チャンク率（地の文のみ）を、割合バー付きで表示する。表示する閾値はサーフェスで 異なる:
  - **cal-viewer 詳細パネル**: **14/20/30 の 3 数字**を「14:X% / 20:Y% / 30:Z%」の順で並列表示。
    バー幅は short30 側から算出。
  - **Chrome 拡張の作品ページ**: **14/20 の 2 数字**を「14:X / 20:Y」の順で並列表示。short30 は
    既存作品の分布で saturate しており（良/駄ともに 70%以上の帯に集中して判別力が薄い）、 かつ狭い
    value 列に 3 数字を並べるとレイアウトが崩れるため、表示からは落とす。data には 残す。バー幅は
    short20 側から算出（残った 2 閾値の重篤上限）。
  - **cal evaluate（CLI）**: 表形式で「<14 / <20 / <30」の 3 列。文字幅に余裕があるので 3 数字を
    そのまま出す。

  いずれのサーフェスでも、14 は表示専用でスコア・警告色には参加させない。
- **短行率の表現**: 短行率は高いほど「1行の情報量が少ない＝要注意」なので、バーは要注意色
  （赤系）で示す。

## 較正による評価軸昇格（将来）

表示で傾向を観察したのち、既存の較正ハーネスで、既存12指標を統制した上での増分説明力
（新指標が既存指標では説明できない部分をどれだけ説明するか）を測る。ジャンル・サイト・
会話率・作品長を揃え、短さの閾値は訓練データ側で選んで検証データ側で再現できた場合にのみ
昇格候補とする。有望な第一候補は地の文の短行率。単体では「短い＝薄い」に反例（キレのある
短文・会話劇）があるため、短文率×語彙反復・短文率×会話率といった複合条件も併せて検討する。
